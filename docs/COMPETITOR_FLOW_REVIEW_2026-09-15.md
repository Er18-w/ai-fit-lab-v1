# 竞品录屏流程评审与“个人外形 Agent”启示

日期：2026-09-15  
证据范围：用户提供的两段手机录屏，分别约 52 秒与 80 秒。评审只针对录屏中可见流程，不推断未展示的后台能力、算法精度或商业数据。

## 一、竞品 A：功能集合型产品

### 可见流程

1. 首页：天气与日常穿搭推荐入口。状态：入口丰富，但核心任务不够突出。
2. AI 试穿：数字模特、真人照片换装、模特照换脸三种方式。状态：输入方式清楚。
3. 真人换装：上传本人照片，并可从单品、组合、拍照、相册导入商品。状态：流程可理解，值得借鉴。
4. 个人信息：要求手工填写身高、体重、胸围、腰围、臀围、肩宽以及上下装信息。状态：信息完整，但初次使用负担较重。
5. 商城：瀑布流商品推荐。状态：商业入口强，容易削弱“认识用户”的主线。
6. 衣橱：空状态要求先添加衣物，达到一定件数后解锁推荐。状态：目标明确，但把核心价值推迟到用户完成录入之后。
7. 发型发色：上传自拍、选择性别、发型与发色。状态：能力独立，未看出与身体档案、衣橱共享数据。

### 值得吸收

- 试穿支持“选单品、选组合、拍商品图、传商品图”四种商品入口。
- 用天气和具体生活场景触发穿搭，比单纯打开衣橱更自然。
- 每项能力都有可见输入，不把 AI 包装成无条件自动完成。

### 不应照搬

- 首页同时承载商城、活动、试穿、发型、衣橱等入口，产品心智容易碎片化。
- 大量功能像彼此独立的小工具，没有清楚证明它们共享同一个“我”。
- 初次建档以长表单为主，用户在获得价值前需要投入过多。
- 商城和积分信息太靠前，会让产品像导购平台，而不是个人 Agent。

## 二、竞品 B：场景搭配与衣橱型产品

### 可见流程

1. 首页：场景搭配、单品搭配、Copy Look、DIY 搭配。状态：任务入口明确。
2. 场景搭配：读取地点、天气、日期，选择日常、工作、约会、运动、旅行、聚会、正式等场合。状态：上下文输入清楚，值得借鉴。
3. 衣橱：分类衣橱、创建衣橱、同款快速导入。状态：个人资产概念明确。
4. 单品/衣物录入：从图片中选择衣物并建立分类。状态：路径可见，但录入成本仍高。
5. 试穿结果：真人/模特大图，下方展示多套推荐搭配并允许继续试穿。状态：结果直观，但录屏无法证明是否稳定保持同一个人的身份和身体比例。

### 值得吸收

- 先问“今天要去哪里、天气怎样”，再给方案，符合真实决策方式。
- 衣橱是长期资产，不只是临时上传区。
- 结果页允许连续比较不同搭配，形成探索闭环。

### 不应照搬

- 积分、签到和推广内容干扰核心任务。
- 多个搭配入口可能让新用户不知道应该从哪里开始。
- 结果缺少“为什么适合我”的解释，也没有展示身体档案怎样影响了推荐。
- 从录屏看不出衣橱、身体特征和试穿模型是否由同一用户数据底座连接。

## 三、对“自如”的直接结论

“自如”不应该以功能宫格作为第一层结构。第一层应当只有三个长期对象：

1. **我**：稳定的外形档案、标准照片、身体比例、偏好、历史与数据可信度。
2. **我的衣物**：已有衣橱，以及当前临时查看的商品。
3. **我的目标**：由 Agent 接收自然语言需求，决定调用搭配、试穿、尺码或后续其他能力。

尺码不是产品中心，而是 Agent 在用户准备购买商品时调用的一项“购买判断工具”。发型、体态和身形目标也不是首页并列主按钮，而是后续接入同一外形档案的能力。

## 四、比赛版最小闭环

```text
首次建档
  → 生成可查看、可修改且带可信度的“我的外形档案”
  → 导入 3～6 件个人衣物
  → 用户说出一个场景与目标
  → Agent 从衣橱选择一套并说明理由
  → 生成保持本人身份与大致比例的试穿参考图
  → 用户反馈喜欢/不喜欢及原因
  → 档案与偏好得到一次更新
```

这条链证明的不是“我们也能 AI 生图”，而是“同一个人的数据被连续复用，并让下一次决策更了解他”。

## 五、比赛版真假功能边界

### 必须做真的

- 建档数据能保存并被后续流程读取。
- 照片和衣物都绑定到同一个用户档案。
- 衣物图片能够形成基础标签；低置信度允许用户修改。
- Agent 根据场景、天气（可用演示数据）、身体比例、衣橱和偏好生成结构化搭配理由。
- 至少一条真人试穿链路实际调用图像能力，失败时有明确提示。
- 用户反馈能写回偏好，下一次推荐有可观察变化。

### 可以先半真半演示

- 身体比例：先用人工确认值或有限视觉估算，不声称形成精确 3D 人体。
- 尺码推荐：保留现有 T 恤规则引擎，只在数据充分时给确定结论。
- 商品推荐：使用少量经过结构化的示例商品，不做完整商城。

### 只展示未来入口

- 发型与发色。
- 体态视频分析。
- 减脂后外形预测与长期训练规划。
- 鞋履精确适配。
- 完整三视图或可自由旋转的 3D 数字人。

这些能力如果在比赛版同时做真，会同时引入身份保持、人体测量、医疗边界、生成可信度和大量数据问题，反而削弱主闭环。

## 六、当前最大的三个待验证假设

1. 同一套用户标准照片，经过多次换装后能否稳定保持脸、身高比例和主要体型特征。
2. 用户是否愿意为了首次价值上传标准照片并录入至少三件衣物。
3. Agent 使用身体档案后，给出的搭配是否比只看衣物和场景更有可感知的个性化差异。

下一阶段应优先用最小实验验证这三件事，再决定是否投入完整外形数据库和更多能力。
